# ESP32 实时语音

ESP32 的 Codex 菜单在“新建任务”下提供“实时语音”入口。通话使用当前任务的身份，进入独立像素动画页；静音、结束和音量在设备上操作。

## PC 音频配置

在语音设置中选择 ESP32 麦克风及对应的虚拟音频注入设备，再刷新“Codex 回答音频设备”，选择一个专用于回答的输出设备并保存。回答输出与麦克风注入必须使用不同的音频通道。所选回答设备的音频会被回传到 ESP32，因此应避免其他应用同时向它播放声音。

PC 将 Windows 音频设备名称与 Codex 浏览器音频设备精确匹配。设备无法唯一匹配、原生语音不可用、任务身份变化或原生连接未确认时，会返回错误并停止采集。当前适配针对 Codex Desktop 26.915.4065.0 的内部实现，客户端升级后需要重新验证兼容性。

当前采用轮流说话：助手回答时停止麦克风上传，回答结束后恢复。尚未验证设备回声消除及自然插话；设备端不提供未经验证的原生打断控件。

## 会话与音频协议

控制消息为 `realtime_start`、`realtime_end`、`realtime_mute`。开始消息带 `requestId`、`host_id`、`thread_id`、`stream_id`；PC 返回相同身份的 `realtime_status`。只有已确认连接且 `acceptsAudio=true` 时设备才上传音频。

上行 `realtime_audio_input` 使用单声道 16 kHz / 60 ms Opus，`generation=1`，带递增 `sequence` 和 base64 `data`。下行 `realtime_audio` 使用单声道 16 kHz / 20 ms Opus。`realtime_audio_clear` 推进下行播放代数并清空旧音频。每帧原始 Opus 上限 4096 字节；双方拒绝过期会话、过期代数及乱序帧。

断线、任务切换和结束通话均关闭麦克风上传、清理播放及 PC 捕获资源。PC 对音频队列设置上限，避免网络阻塞后持续积压旧回答。

## 验证边界

自动化测试覆盖会话身份、启动确认、取消竞态、静音、过期音频和失败清理。原生 helper 可通过只读 `capture_list` 检查输出设备枚举。编译及测试通过不代表物理设备通话已通过；刷机后仍需验证麦克风到 Codex、回答到扬声器、状态动画、静音/结束、断线恢复和任务切换。
