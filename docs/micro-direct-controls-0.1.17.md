# Micro 直接控制与语音响应

日期：2026-09-17。PC 版本：0.1.17。核对的本机 Codex 版本：26.911.7940.0。

## 使用方式

退出运行中的桥接程序，启动 `build/pc/CodexRemote-Portable-0.1.17.exe`。
PC 更新包含语音与控制路径的变更；配套固件更新用于新任务参数页的显示和取消自动读取参数。

在 Codex 的「设置 → Codex Micro」中配置：

1. 麦克风键保持「按住说话」，使用合并麦克风键布局。
2. 保留 CODEX 发送键，对应 `composer.submit`，通常是 ACT12。
3. 选择一个命令键，例如原“在新任务中继续”的 ACT09，把键帽／动作改为「新建任务」NEW（`newTask`）。桥接按当前布局寻找该命令，不会修改用户配置。缺少绑定时，设备的新建任务操作会给出配置提示。
4. Agent 键继续按用户配置跟踪最近任务、固定任务、优先任务或自定义任务。桥接按单击唤起设置发送一次或两次 AG 按键。

[官方 Micro 设置说明](https://learn.chatgpt.com/zh-Hans/docs/features/codex-micro)介绍了布局预览中的命令键自定义方式。

## 当前路径

| 操作 | 执行方式 |
| --- | --- |
| 语音开始 | 复用音频通道，直接发送 Micro ACT10 按下 |
| 松开并发送 | 排空本次音频，发送当前绑定的 composer.submit，再释放 ACT10 |
| 取消语音 | 并行丢弃音频；Micro 唤起对应槽位，发一次 Esc，再释放听写键 |
| 切换任务 | AG00～AG05；按设置发送单击或双击 |
| 新建任务 | 当前布局中绑定 newTask 的 Micro 命令键 |
| 已有任务的模型／强度／Fast | 按任务 ID 通过本地 IPC 设置，并等待参数回读 |
| 新任务参数 | 使用 Codex 当前默认参数，首条消息发送并绑定任务后可调整 |
| 停止任务 | Micro 唤起任务，发送两次 Esc，间隔 100 ms |
| 新任务 ID 同步 | 首条消息提交后，通过 Ctrl+Alt+L 读取前台任务链接，与新增 client-thread 绑定候选匹配 |

语音开始、结束、取消、切换、新建、参数设置和停止这些生产调用路径不使用 UIA。问答卡片等其他功能沿用各自实现。

当前客户端的 Micro 松开事件执行听写的 insert 路径，未发现独立的 Micro 丢弃听写命令。Esc 路径按用户确认采用。新任务尚无任务槽位时，取消只通过 Win32 唤起 Codex 窗口再发送 Esc，不点击 Agent 键另开任务。

新任务 ID 回读不读取 UIA。请保留「复制深层链接」为 Ctrl+Alt+L，并保持刚提交的新任务在前台直至同步完成。程序恢复自己复制的任务链接之前会核对剪贴板序号，避免覆盖用户后续复制的内容。

## 行为边界

- 直接听写操作作用于 Codex 当前接收 Micro 输入的页面。PC 与设备的请求、任务、连接代次校验仍在，但不再读取界面核验当前输入框。若在 PC 手动切换页面，应先在设备选择相应任务。
- 槽位选择、取消和停止需要任务仍在当前六个 Micro 槽位内；槽位变化时拒绝继续投递，不根据标题猜测目标。
- 键盘 helper 常驻预热，只接受取消 Esc、停止 Esc、复制任务链接三种请求。发送按键前及两次 Esc 之间检查 Codex 前台窗口；超时不自动重放。
- 新任务创建、语音发送和停止只报告操作已投递，不将 HID／键盘回执标成 Codex 已完成。真实消息和任务状态继续从 IPC 同步。
- 普通取消保留音频 helper 和端点，等待清理完成才允许下一次会话，避免旧音频混入新会话。
