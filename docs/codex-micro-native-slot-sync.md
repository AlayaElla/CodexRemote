# Codex Micro 任务槽位同步

2026-09-17。

ESP32 任务列表使用 Codex Micro 当前拥有窗口的实际六槽位结果。槽位索引、任务主机与 ID、标题和空槽均保留原值；切换 recent、pinned、priority、custom 来源时，列表直接使用 Micro 的新结果。

PC 桥接每秒读取一次本地运行时快照。Micro 调整顺序后，已选任务继续通过主机与任务 ID 关联。任务内容、模型与操作确认仍沿用现有任务状态 IPC。

## 本地运行时读取

- `src/core/codex-micro-slots.js` 核对 Codex 主进程 PID 和可执行文件路径，再建立带随机认证令牌的本地命名管道。
- 初始化时临时连接本机 Node inspector，安装固定的只读槽位查询；由桥接开启的 inspector 在初始化后关闭。后续轮询只使用命名管道。
- `src/platform/codex-micro-runtime.js` 从 Micro 实际使用的槽位 atom 读取结果，并确认唯一的 Micro 拥有窗口。
- 关闭桥接时释放管道；桥接异常退出后管道空闲 30 秒自动关闭。
- 原生快照不可用或结构校验失败时，设备槽位显示待同步，恢复连接后重新读取。

当前适配并实测 Codex 安装包 `26.911.7940.0`，运行时应用版本 `26.911.61220`。读取依赖 Codex 内部模块导出和运行时状态结构；客户端升级改变这些接口时，需要更新适配代码。

## 验证

- 原生六槽位快照与桥接发送快照的索引、主机、任务 ID、标题逐项一致。
- 在打包使用的 Electron `28.3.3` 内运行修复包代码，六项任务均同步成功。
- 回归覆盖四种来源、原生空槽、重排后保持任务选择、来源切换、读取失败与恢复、错误进程拒绝注入、后续读取复用命名管道。
- 任务控制、草稿绑定、草稿生命周期、菜单集成和连接生命周期检查通过。
- 尚未在 ESP32 屏幕上完成验收。
