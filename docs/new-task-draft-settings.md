# 新任务、草稿参数与 ESP32 消息同步

点击新建任务后，ESP32 立即收起菜单并进入“正在准备新任务…”页面。电脑桥接创建原生草稿并记录输入框身份，随后异步读取模型、推理强度和 Fast，通过独立的 `codex_state` 更新设备。参数扫描不再阻塞切页响应；原生输入框及参数扫描未完成时，语音入口等待准备完成，避免同时操作电脑输入框。

进入模型页会重新读取草稿参数。模型匹配覆盖 `GPT-6-Astra`、`GPT-6 Astra`、`6 Astra` 和 `Astra` 等完整名称，同时读取 Toggle 和 SelectionItem 的选中状态。重复的父子节点不会把已选状态覆盖成未知。首次捕获输入框尚未就绪时，参数读取可以补充捕获。

模型、强度、Fast 各有就绪标记。Fast 控件无法回读时显示具体原因和“待同步”，模型与强度仍可独立使用；未知的 Fast 不会被当作已关闭。读取支持“启用快速模式”和已启用时的“启用标准模式”两种按钮名称。草稿状态和参数完成事件推进同一个状态版本号，较晚到达的操作响应不能覆盖更新的参数。

修改走 Codex 原生模型菜单，逐次回读确认；修改模型时保留受支持的强度，否则使用新模型的默认强度，并关闭不受支持的 Fast。尚未得到实际回读时，设备不会把期望值显示成已经生效。

草稿操作使用 `draft_id / stream_id / host_id`，与既有任务的 `slot / thread_id / host_id` 分开校验。电脑切换页面或输入框、设备选择其他任务、首次发送、断线后，过期操作不能继续修改草稿。读取失败会显示原因，重新进入模型页可以重新读取同一个输入框。

## 首条消息后的任务绑定

首次发送后保留草稿关联，ESP32 显示“已发送，正在同步任务…”。电脑桥接立即尝试同步，以 500 ms 间隔检查新增加的 `client-thread-bindings-v1`，再以当前 Codex 页面复制出的任务链接确认具体 ID，随后订阅该任务的参数和对话。原生链接读取最多每 2.5 秒尝试一次，避免反复触发快捷键。ESP32 语音发送会记录提交时间；直接在电脑输入首条消息也会由绑定检查发现。

ESP32 语音提交后，绑定检查达到 30 秒仍未成功会进入可恢复错误状态，显示原因及“重试同步”。一次正在执行的原生检查结束后才结算超时。重试仅重新确认任务身份，不会再次发送消息；也可以从任务菜单直接选择刚创建的任务。`NewTask` 日志记录准备、参数完成、提交、绑定完成或失败的耗时及参数就绪状态。

新任务不在六个快捷槽位时，通过 `activeTask` 保持选中；参数操作携带 `slot: -1`、任务 ID 和连接标识，通过任务定向 IPC 更新。任务进入或移出快捷列表时保留对话及参数。电脑端创建失败时保留原先选择的任务，并显示错误。

任务链接读取使用当前 Codex 的默认“复制深层链接”快捷键 `Ctrl+Alt+L`，检测到快捷键被禁用、改绑或占用时显示原因。读取要求刚发送的任务仍位于原 Codex 窗口前台；过程中保存剪贴板，确认复制结果且剪贴板未被随后修改时恢复原内容。若用户在确认前切换到另一个同时创建的新任务，当前实现会跟随前台显示且在本次新增绑定集合内的任务。

当前安装版 Codex 的草稿 ID 绑定通知位于私有渲染器通道，外部任务 IPC 未提供该订阅，因此本版仍保留上述页面链接确认方式。

## 语音上划取消

按住录音使用录音色；上划进入取消区域时切换为红底、深红色文字和图标（`#7F1D1D`）、白色边框，并显示取消提示，移回区域后恢复录音色。默认及 `LV_STATE_PRESSED` 的背景样式一起更新，避免持续按住时被通用按钮的按下颜色覆盖。

## 追加消息与数量上限

电脑对话投影包含原生 `steeringUserMessage`，因此执行中追加的用户消息也会同步到 ESP32，并按客户端、服务端消息标识合并重复回显。

ESP32 最多保留最近 **10 条用户或 Codex 消息**。电脑下发、设备解析和对话渲染均限制数量；追加第 11 条时移除最早消息，渲染层删除对应 LVGL 气泡。图文混合内容按一条消息计数。审批、提问卡片沿用独立的交互生命周期。Codex 电脑端历史记录不受设备显示上限影响。

## 涉及的两端源码

- `D:/AI/CodexRemote`：草稿绑定、原生参数读取、任务状态、追加消息投影、下发上限。
- `D:/AI/MetalioClaw4-AgentUI`：菜单和对话状态、当前任务参数操作、10 条消息保留及气泡删除。

电脑桥接需要将 `src/platform/codex-draft-settings.ps1`、`src/platform/codex-draft-target.ps1` 与 `codex-shortcuts.ps1` 一起从 ASAR 解包，配置已经补齐。脚本保留 UTF-8 BOM，供 Windows PowerShell 正确读取中文控件名称。两端均需要使用修改后的源码才能验证完整流程。
