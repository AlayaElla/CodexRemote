# ESP32 最近任务顺序修复

2026-09-14，本机 Codex 26.908.4834.0，Micro 来源为 `recent`。

## 原因

PC 桥接直接读取 `threads` 表，未过滤内部任务。用户反馈的三个空条目对应 `处理 ESP32 PC 断连显示` 下的 `device_connection_ui`、`firmware_transport`、`codex_ipc_lifecycle` 子代理，数据库中均为 `thread_source=subagent` 且无标题。它们占据了六槽位列表的位置；任务状态可用时显示空闲，没有实时拥有者时显示待同步。

此外，桥接按 `recency_at_ms` 排序。本机 Micro 的最近任务选择器合并可见任务后按 `updatedAt` 降序，二者并非同一时间字段。

## 修改

- SQLite 查询在限制 256 条之前筛选未归档的用户任务，兼容没有 `thread_source` 的旧记录，同时排除旧版 `source` 中的子代理记录。
- 最近任务按 `updated_at_ms` 排序，缺少毫秒时间时使用 `updated_at * 1000`。保留活动时间供其他模式使用。
- 未命名的真实用户任务继续保留。任务选择仍按主机与任务 ID 校验。
- 修改位于 PC 桥接，不涉及 ESP32 固件。

## 验证

任务列表、桌面状态、任务控制测试通过。新增真实 Windows PowerShell/SQLite 回归用例，覆盖 300 个子代理、300 个归档任务、内部审核与语音任务、旧记录、合法空标题、更新时间和活动时间相反的情况，并确认读取没有修改数据库。

本机只读 IPC 回读得到六个有标题且 `synced=true` 的任务：排查 ESP32 任务顺序异常、检查新建任务问题、处理 ESP32 PC 断连显示、排查 ESP32 消息与按钮问题、优化 ESP32 Codex 任务定位、修复 ESP32 LVGL 构建失败。前两项当时为执行中，其余为空闲。最近任务会随任务更新而重新排序。

修正版 `build/pc/CodexRemote-Portable-0.1.11-task-order-fix.exe` 基于已有 0.1.11 包单独生成，仅替换任务读取与排序文件并调整包版本，避免包含其他正在进行的源码修改。需启动该版本后设备端才能接收新列表。

验证范围是本机任务读取、IPC 状态和程序包内容；尚未在 ESP32 屏幕上验收，也没有证明远程主机、云任务或其他自动来源与 Micro 完全一致。
