# ESP32 任务消息与状态光环

2026-09-13，PC 版本 0.1.7。需要同时更新 PC 桥接程序和 ESP32 固件。

## 显示行为

- 任务身份由 `hostId + threadId` 确定。六个 Micro 槽位可以重新绑定，消息不会沿用旧绑定。
- PC 从 Codex 桌面本地 IPC 的任务流读取对话。切换任务时，状态与该任务最近 3 条用户/助手消息在同一个快照中发送，按时间从旧到新排列。
- 后台任务持续更新各自缓存。当前任务不接收其他任务的消息、状态或审批弹窗。切换后会隐藏前一个任务的审批弹窗。
- 回到 Codex 页面、Wi-Fi 重连会重新请求快照，不必等待下一条 Hook 事件。任务尚未同步时显示“正在同步消息…”，空任务显示“等待新消息”。
- 流式内容按消息 ID 更新，PC 最多每 200 ms 合并一次同一状态下的更新。用户切换和运行状态变化立即发送。旧版本快照及延迟的操作结果不能回滚当前任务。
- 光环使用项目主题色，运行中旋转、等待操作时用警示色、录音时绿色、错误时红色静态边框。任务空闲或连接断开时隐藏。连接设置中的开关仍保存到设备。
- 光环位于菜单和审批面板之上，不接收点击。动画只移动边缘的小矩形，计时器随组件销毁；松开语音按钮不会终止它。

## 协议

`codex_state` 仍为版本 1，增加 PC 进程唯一 `streamId` 与当前任务的 `conversation`：

```json
{
  "streamId": "pc-process-id",
  "revision": 42,
  "selectedSlot": 1,
  "conversation": {
    "hostId": "local",
    "threadId": "task-b",
    "ready": true,
    "messages": [
      { "id": "message-id", "role": "codex", "text": "消息正文" }
    ]
  }
}
```

上例省略原有任务槽位、模型和能力字段。未选择任务时 `conversation` 为 `null`。ESP32 同时校验选中槽位与会话身份。`codex_sync` 请求 PC 重发当前快照。

只保留用户和助手可见文本，不传工具输出、推理过程或附件数据。每条消息最多 4096 字节 UTF-8，长文本以省略号结尾；每个设备快照只附当前任务最近 3 条，其他任务只传标题/状态/设置。历史来源支持当前 canonical `turnHistory` 和旧的 `turns` 结构，并按桌面顺序应用增删改补丁。

## 验证

- PC：`npm test`，30 个测试入口通过。包含真实 WebSocket 基础测试、IPC 分帧/补丁、后台 A 更新时前台 B 保持不变、切回 A 回显更新、旧快照不可变、无身份事件隔离。
- 真实桌面只读验证：已绑定任务通过 IPC 返回最近 3 条消息及 working 状态，实际设备快照为 4531 字节。仅保存角色/数量/字节数报告，没有保存对话文本。该验证未点击 Micro 或改变桌面任务选择。
- 固件：`node scripts/test-codex-menu-state.cjs`，覆盖三条上限、host/thread 隔离、延迟快照/操作结果及 PC 重启后的新 stream。
- 实际 LVGL 组件：`node scripts/test-codex-menu-render.cjs`，10 个渲染场景通过，覆盖原有菜单、光环旋转帧差异、边缘完整一圈坐标、菜单层级、关闭后像素恢复、销毁后计时器清理。
- 渲染产物位于固件仓库 `build/codex-menu-render`，使用实际生产组件和字体，任务内容是固定测试数据。

以上为桌面只读同步、自动化与离屏渲染证据。设备刷入后的实机触摸、帧率和 Wi-Fi 连续运行需要硬件验收；本次不自动刷写。
