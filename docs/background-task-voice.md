# 后台任务切换与转录提示

PC 桥接版本：0.1.16。

ESP32 选择已有本机任务时，桥接通过 Windows MSAA 调用 Codex 的原生任务按钮。操作前后均只读查询任务数据库，核验任务 ID、当前标题及标题唯一性，再检查主页面和输入框。任务选择不再调用任务深链或 Micro 的唤起窗口按键。

窗口最小化时，桥接临时以不激活窗口的方式显示 Codex，完成任务切换后恢复最小化。若操作期间用户主动激活 Codex，则保留用户的窗口状态。

Micro 录音和已配置的发送按键继续通过 HID 投递；发送按钮及取消按钮的辅助调用使用 MSAA。桥接读取 Codex 的原生“取消转录”控件，将实际转录状态同步为 ESP32 的“转录中...”。已有任务的发送结果通过目标会话的新用户消息或原生排队消息确认；超时或连接/任务变化时显示未确认结果，不重发语音。

执行中的任务遵循 Codex 的原生后续消息设置：queue 显示“已排队”，steer 显示“已引导”。空闲任务显示“已发送”。草稿转录后继续交由现有的新任务绑定流程确认身份。

## 使用条件

- 同名、已归档、刚更名或未出现在侧栏中的任务会拒绝后台导航。可先在电脑侧栏展开对应项目。
- 后台语音要求只有一个可用的任务输入框；打开侧边聊天时会提示关闭，避免 Micro 把录音送往另一输入框。
- 新建任务、草稿身份绑定及原生问题回答仍使用各自原有流程，可能需要前台窗口。

## 验证边界

- 本机 Codex 26.908.4834：实际切换到另一已有任务并返回；前台测试窗口保持不变。
- 最小化场景：切换成功，结束后仍最小化，前台测试窗口保持不变。
- 自动化覆盖后台导航身份不匹配、转录提示、排队确认、超时、任务变化以及转录期间请求归属。
- ESP32 C++ 主机测试覆盖录音、取消、迟到状态和断连；安装包构建不代表已刷机或实际麦克风端到端验证。

装包后依次检查：在其他应用前台切换已有任务；按住说话并松开，确认出现“转录中...”；等待“已发送/已排队/已引导”；再检查 Codex 最小化时相同流程。
