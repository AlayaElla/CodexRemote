# Micro 亮度与自动调暗同步

PC 桥接从当前 Codex Micro 的配置模型读取正常亮度和自动调暗时间，随有序 `codex_state.microDisplay` 快照下发。配置更新沿用现有约 1 秒的 Micro 读取周期。协议版本和产品版本不变。

## 设备行为

- 同步范围为 ESP32 的 Codex 页面，桥接和 Codex 连接有效且配置可用时生效。
- 正常背光跟随 Micro 百分比，最低保留 5%，避免 Micro 设置为零时设备不可见。
- 自动调暗支持关闭、30 秒、1/3/10/30 分钟及 1 小时。关闭时保持正常亮度。
- ESP32 按自己的无操作时间计时，调暗亮度为 `min(正常亮度, 15%)`，保持当前画面，不进入原有全黑待机。
- 触摸、正在录音、Micro 槽位任务/状态/选中状态变化和语音状态变化会恢复正常亮度。更改配置也会重新计时。
- 重复快照、心跳和普通聊天文字更新不会重置计时。
- 退出 Codex 页面、连接失效、配置缺失或无效时恢复设备保存的亮度及原有待机策略；同步不写入设备 NVS。

时间同步指同步超时设置，并非要求两块设备在同一毫秒调暗。ESP32 上的独立触摸活动会重新计时。

## 实现与验证

`codex-micro-runtime.js` 读取配置模型；`codex-micro-slots.js` 校验并生成活动标识；`codex-desktop-state.js` 将其纳入变更检测与状态快照。ESP32 的 `micro_display_policy.h` 校验配置并计算背光目标，`IdlePower` 负责临时覆盖和恢复。

定向测试覆盖配置变化、重复同步、连接断开、无效配置、超时边界、计时回绕、低亮度限制，以及现有任务控制和语音处理回归。通过现有只读同步器实测运行中的 Codex 可返回 100% / 3 分钟配置。

物理屏幕的 15% 可读性、亮度渐变和触摸恢复仍需刷入固件后验收。
